# Deferred Review Register

This file records governance topics that were discussed but are intentionally not yet encoded as active policy files.

## Purpose

The Governance repo should keep moving without losing sensitive or high-risk design threads. Deferred items belong here until they can be safely phrased, reviewed, and assigned to the correct repo or legal/treasury process.

## Deferred Items

### 1. External bridge policy

Reason deferred: detailed external transaction flows require legal, tax, treasury, and compliance review.

Safe next step: write a non-operational requirements note that defines review categories, ownership assumptions, and questions for counsel.

### 2. Public-market and payout mechanics

Reason deferred: public-market language may create regulatory and platform-safety concerns.

Safe next step: keep current docs limited to internal credits and review receipts until legal review is complete.

### 3. Governance license draft

Reason deferred: policy-aligned licensing needs legal review before publication and should not be treated as enforceable without counsel.

Safe next step: draft a values statement first, then convert to license text after review.

### 4. 30-day external pilot roadmap

Reason deferred: earlier direct creation attempts were blocked. The concept should be reframed as an internal activation checklist rather than external operational outreach.

Safe next step: add short, neutral task cards after validation passes.

### 5. Monolithic bundle source

Reason deferred: large combined bundle was blocked. Smaller direct files are now preferred.

Safe next step: keep using individual files and the conversation-ingestion workflow. Reintroduce bundle ingestion only for smaller bundles.

## Review Criteria

A deferred item may be promoted into a normal governance doc when:

1. It is scoped to policy, not operational execution.
2. It contains no private data, credentials, or sensitive artifacts.
3. It has an owner or review domain.
4. It passes the docs validation workflow.
5. The handoff is updated after the file is added.
